# 0021: A workspace, and tagging who spoke (speaker awareness, stage 1)

Date: 2026-11-15
Status: Accepted

## Context

Lucy will need to tell apart the people talking to her (guests, per-person memory, a "listen to this conversation" mode). The first step is to know, for each voice utterance, who it probably was, without changing anything she does. Speaker recognition comes from the `voice-fingerprint` package (WeSpeaker ResNet34 on ONNX Runtime), whose documented API takes file paths. Voice recordings are sensitive, and Lucy makes no network requests of her own by default.

## Decision

- **A workspace.** `[workspace] path` (default `data/workspace`, gitignored with the rest of `data/`) is Lucy's own directory for files her code writes and reads. `lucy.core.workspace.Workspace` creates it and named subdirectories on demand with mode 0700, accepts only plain names, and refuses any path that resolves outside it. Today: `speakers/` (the speaker book `book.npz` and enrolment clips under `speakers/NAME/`) and `utterances/`. No tool gives the chat model access to it.
- **Stage 1 is a tag only.** With `[speakers] enabled = true`, each voice utterance is written as a 16 kHz mono WAV to `utterances/<UTC time>_<message id>.wav` and identified on a worker thread while it is transcribed. When the transcript is ready the turn waits at most `wait_ms` (default 150) for the result, then goes on with or without it. `UserMessage` gains optional `speaker` (accepted best match, else None), `speaker_score`, `audio_path` (relative to the workspace, only while the clip is kept) and `audio_s`; old events load unchanged. The prompt, history, memory extraction, confirmation and tools read only `text`, so the model request is identical with or without a tag (tested). The voice clients print `you (NAME)>` when a name is known, and the timings file records the speaker.
- **Retention.** Clips are kept `keep_utterances_days` (default 1) and pruned oldest-first beyond `max_utterances_mb` (default 200), at startup and every 50 utterances; 0 days deletes each clip right after identification. Clips are kept at all so that the user can later ask Lucy to identify or tag the voices in them; the period is short because family members also use Lucy and their voices end up in these clips.
- **Explicit download.** `lucy speakers download` fetches the weights into `data/models/speaker/`. The adapter always passes that file path to the library, whose weight resolution then never contacts the Hub (it returns the path or raises). If the file is missing, tagging is off with one notice naming the command.
- **A voice match is never an authorisation.** The embeddings are not anti-spoofing: a recording of an enrolled voice scores as high as the person. Later stages may use the tag to choose whose memory to use, but never to allow an action.

## Consequences

- Identification is ~15 ms for under 3 s of speech, ~140 ms at 3 to 4.5 s and ~280 ms at 12.7 s on this Mac, warm, so it usually finishes within transcription plus the wait bound. Under 3 s of speech (after the library's energy VAD) is zero-padded to its 3 s window, and such clips scored near 0 against an enrolment of the same voice: short replies ("yes") will mostly be untagged until that is improved upstream. `audio_s` is recorded so accuracy by length can be measured.
- The threshold (library default 0.40) is uncalibrated for Lucy's microphone.

## Amendment (2026-11-15): enrolling a voice by asking

The user can say "enrol my voice" or "enrol Asha's voice" in `lucy voice` or `lucy listen`.

- Two tools, because a tool has one risk tier: `enroll_voice` (act) for a name not yet enrolled, refusing an enrolled one with a message naming `replace_voice`; `replace_voice` (dangerous) for an enrolled name, through the confirmation flow ("Replace the enrolled voice for Yogesh?"). The model only picks the tool by whether it is a first enrolment; the existence check and the question are code. Names are short and plain (letters, spaces, hyphens) and become `speakers/NAME/`; placeholders and phrases ("my voice", "me", "user", anything with "voice" or starting "my "/"the ") are refused, telling the model to use the user's known name or ask; an all-lowercase name is title-cased.
- The tools do not record. A successful call is the request: the voice session sees the call start and finish on the bus (`ToolStarted`, `ToolFinished`, ADR 0003) and, once the turn has been spoken and still holding the floor, leads the enrolment in code (`lucy.voice.enrol`, `VoiceSession._enrol`). The orchestrator stays stateless. In `lucy chat`, with `[speakers]` off or without weights, the tools refuse with what to do.
- Each sentence is announced by a short cue ("First sentence.") and shown on screen only once the cue has played and the session is listening (past the post-playback drop), so a reading started the moment it appears is not clipped; TTS never reads the sentence, so the user is not led to imitate Lucy and her voice is never in a clip. Each next utterance is a clip, not a `UserMessage`: no model turn, no speaker tag, nothing for memory extraction, nothing in `utterances/`. A clip under 3 s of speech, or one whose transcript shares under half of the sentence's words, is asked again (two retries, then the enrolment stops). "cancel" or "stop" as the whole utterance, Enter, or 20 s of silence stop it. Clips stay in memory until all are accepted, so a stopped enrolment leaves no files.
- Then the clips are written to `speakers/NAME/` (replacing what was there), the old enrolment is removed, the new one enrolled, and one clip identified as a check. The outcome is published as a `TimerFired` (`voice_enrolment`) whose handler says it, so it is spoken and logged as a code-authored `AssistantMessage` like a reminder delivery; the next model turn sees it in history.
- The wake listener treats an enrolment as awake (no wake phrase between sentences) and returns to its follow-up window afterwards. A reminder due meanwhile waits for the floor.

Caution: today the speaker tag changes no behaviour, so anyone may enrol or replace a voice. Once the tag gates anything, enrolling and replacing must be limited to a recognised owner.

2026-11-24: short clips. The cause of near-zero scores under 3 s of speech is confirmed in `voice-fingerprint` 0.1.1: the speech is zero-padded to the 3 s window and the filterbank's mean normalisation then runs over the padded frames, which skews every real frame. The adapter now does the library's levelling and VAD itself (`recognizer.preprocess`), repeats the speech end to end to fill the window, embeds it and scores against the book's centroids; enrolment goes through the same path (a no-op for clips of 3 s or more, which the enrolment flow requires). On the owner's real clips at the 0.40 threshold, recognition went from 0 of 16 to 3 of 16 under 1 s, 2 of 42 to 30 of 42 at 1 to 2 s and 8 of 14 to 13 of 14 at 2 to 3 s, with impostor false accepts unchanged (2 of 509 short public clips). With the fix, short-clip false rejects are 22% and false accepts 1.0% at 0.35, 12% and 2.4% at 0.30 (`checks/speaker_short`). The threshold was left at 0.40: calibrating it needs other voices recorded on this microphone.
